# annotation 静态页发布

通用静态展示页：每个页面一个子目录，内容为 `index.html` + `data.js` + 相对路径媒体。无后端。默认优先发到 **GitHub Pages（公网 HTTPS，任何人可打开）**；本机或自有服务器仅作预览/备份。

## 页面约定

子目录名 = URL 路径段（示例名 `demo_page/`，实际名由当次任务决定）：

| 路径 | 作用 |
|---|---|
| `index.html` | 壳：样式与渲染逻辑，读取 `window.DATA` |
| `data.js` | `window.DATA = {...}`；媒体路径一律相对本子目录 |
| 媒体目录 | 图/视频等；勿写盘符或机器绝对路径 |

站点根目录另需：

- 空文件 `.nojekyll`（GitHub Pages 关闭 Jekyll）
- 可选根 `index.html` 作目录页

可参考已有公开页的结构（同构即可，不绑定某一仓库路径）。

## 发布渠道（按优先级）

### 1. GitHub Pages — 默认公网方案

适合「发给别人就能打开」。

1. 目标为**公开**仓库，已启用 Pages（源一般为默认分支仓库根目录）。
2. 将完整子目录推上去；公网地址形如：`https://<user>.github.io/<repo>/<subdir>/`
3. 单文件勿超过 GitHub 限制（硬顶 100MB；视频宜压缩或外链）。
4. 推送后等待部署生效，抽查页面与媒体。
5. 若有根目录索引，补上新页链接。

仓库名、用户名、子目录名均由**当次对话**提供或确认，不要写死在步骤里。

### 2. 自有公网机器（可选）

当用户需要 `http(s)://<公网主机>:<端口>/...` 或自有域名时：

1. 用与 Pages **相同**的静态文件树。
2. 在用户指定的公网主机上用 nginx / Caddy / 静态文件服务监听其指定端口，站点根指向该文件树。
3. 确保安全组/防火墙放行；优先 HTTPS（证书由用户环境决定）。
4. 交付可外网打开的最终 URL。

本机局域网 IP **不是**公网；仅同网段可访问时，要明确告诉用户外人打不开。

### 3. 本机/局域网预览（可选）

仅本地验收时：在站点根执行通用静态服务（端口由用户指定，未指定再问或选空闲端口），绑定 `0.0.0.0`，用当次探测到的局域网地址拼接 URL。不要把某次探测到的 IP、盘符路径写进本 skill。

## 新建一页的执行顺序

1. 确认：子目录名、数据与媒体、目标仓库（及是否要额外挂自有公网主机）。
2. 生成 `index.html` + `data.js` + 媒体；路径全部相对。
3. 抽查相对路径是否可解析。
4. **先做 GitHub Pages（公网）**；仅当用户明确要求时再做自有公网机或本机预览。
5. 回复可打开的最终公网 URL（及若有的预览 URL）。

## 成功标准

- 至少有一条**公网**链接，未授权的同事用浏览器可打开并加载媒体。
- Skill 与生成物中无机器绝对路径、无写死的个人目录或某次临时 IP。
- 参数（仓库、子目录、端口、主机）来自当次用户说明或现场查询。
